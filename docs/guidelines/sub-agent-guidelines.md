# Sub-agent Guidelines

本指南只面向拥有创建 sub-agent 能力的主 Agent。任务拆分、状态管理、结果核验和最终整合均由主 Agent 负责。

## 委派边界

- sub-agent 适合承担目标具体、边界明确且能够独立推进的调查、分析、验证、审查或特定范围修改。可并行不是唯一适用场景，但不要委派需要主 Agent 持续协调的高耦合任务。
- 主 Agent 可以委托 sub-agent 为重要判断提供独立分析或证据，但最终决策、任务范围、跨任务整合和对用户的答复仍由主 Agent 负责。

## 任务信息

- 根据任务性质选择合适的 sub-agent 角色，不要在任务消息中重复宿主已经提供的角色定义或项目指令。
- 任务消息应当自包含，并按需提供具体目标、任务对象、范围、交付要求以及完成任务所需的事实。
- 用户在当前会话中提出且适用于子任务的额外规则或偏好，需要显式传递给 sub-agent。
- 不要设定与任务无关的模型、思考深度或其他非必要参数。

## 共享工作区与结果

- 所有 Agent 共享同一工作区，文件变化会立即互相可见。
- 创建多个可写任务前，主 Agent 必须划分明确且互不重叠的写入范围，并避免与自己正在进行的修改重叠。
- 验证要求应与任务风险相称。主 Agent 必须结合实际文件、diff、命令输出或其他证据核验 sub-agent 的结果，不得未经检查就直接采纳。

## 协作生命周期

- sub-agent 运行时，主 Agent 应继续推进不依赖其结果的工作；只有后续步骤确实依赖 sub-agent 时才等待。
- 等待超时不表示 sub-agent 已失效。应先确认其状态和任务价值，再决定继续等待、补充信息或调整方向。
- 只有任务已被取代、方向需要立即纠正、继续执行存在风险或用户要求停止时，才中断正在工作的 sub-agent。
- 已有 sub-agent 只用于继续同一工作流或紧密相关的后续任务，避免无关任务受其既有上下文影响。
