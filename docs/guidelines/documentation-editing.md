# Documentation Editing Guidelines

本指南用于指导需要创建或修改 `docs/` 下由 Git 跟踪的生产文档的任务。

## 表述方式

直接描述实现事实，避免使用带有时间对比、版本迁移或历史状态意味的表述，例如：

- “当前……”
- “目前……”
- “现在……”
- “以前……”
- “原来……”
- “旧版……”
- “新版……”
- “从……改成……”
- “不再……”

需要表达能力时，使用中性陈述，例如：

- “支持……”
- “使用……”
- “由……负责……”
- “通过……实现……”
- “失败后停止重试……”

文档不记录历史状态。除非用户明确要求，不编写变更回顾、迁移叙述或与历史实现对比的说明。

## 修改边界

修改 `docs/` 下的文档时遵循最小变更原则。只修改与用户任务直接相关的文件、章节和段落，不要顺手整理、改写或统一与当前任务无关的内容。

即使发现既有内容不符合本指南的表述要求，也不要在未获得用户同意时主动修改。此类内容可能是有意保留的历史说明、阶段性记录或上下文材料。

如果发现无关内容存在明显问题，可以在回复中说明并建议后续处理；是否修改由用户确认。无法判断某处内容是否属于当前任务范围时，应先询问用户。
