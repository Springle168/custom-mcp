# docs/AGENTS.md

本文件面向维护 `custom-mcp` 项目的 AI Agent，作用范围为 `docs/` 及其子目录。若本文件与用户明确指令冲突，以用户指令优先。

## 文档定位

`docs/` 下由 Git 跟踪的生产文档是开发文档，读者是项目维护者和参与维护的 AI Agent。生产文档应服务于理解、维护、排查和扩展代码，不按普通用户手册、产品介绍或营销材料的风格编写。

默认读者具备相关技术基础。重点记录项目特有的契约、限制、非显然行为和设计原因，不展开通用知识、基础操作，也不逐句转述代码；跨模块约束、安全边界、并发、生命周期和失败恢复等维护所需信息不能因此省略。

## 内容依据

由 Git 跟踪的生产文档以仓库代码中可验证的实现、真实测试的行为为准，描述代码具备的能力、约束、入口、数据流和维护方式。

生产文档不要补充未从代码或用户指令中确认的能力、计划、背景或结论。若代码与生产文档不一致，应以代码中可验证的实现为准修正文档。

## 文档分工

- [DEVELOPMENT.md](DEVELOPMENT.md) 维护开发入口与任务导航，不承载源码细节归属。
- [ARCHITECTURE.md](ARCHITECTURE.md) 维护整体模块边界、关键数据流与资源所有权，不枚举文件职责。
- [PROJECT-STRUCTURE.md](PROJECT-STRUCTURE.md) 集中维护布局树与简要职责：源码完整展开，测试覆盖主题目录与关键公共入口，不枚举普通测试脚本或生成物。
- 专题维护项目特有的契约、机制、取舍和验证条件。必要源码引用随机制说明放置，不附完整源码或测试名录；长专题按相对完整的维护任务组织成概览与子专题。
- [TOOLS.md](TOOLS.md) 维护工具契约与工具索引，不维护添加工具的步骤教程。测试运行规则与通用验证命令由 [TESTING.md](TESTING.md) 维护。
- [CUSTOM-TOOL-AUTHORING.md](CUSTOM-TOOL-AUTHORING.md) 是可脱离仓库提供的独立规范，必须自包含，不链接仓库内部文档。内部专题可以引用它；必要的契约重述不按普通重复内容删除。

## 内容组织

- 同一契约或机制应有明确的主要归属，其他文档通过链接引用，只保留理解当前上下文必需的简短说明，不维护完整副本。独立规范的例外见上述约定。
- 概览保留公共模型、阶段关系和导航，子专题承载具体功能的参数、行为与限制。按职责和维护任务拆分，不按篇幅机械拆分，也不为对应源码目录而创建空泛的中间概览。
- 文件布局树与逐文件职责集中在项目结构文档；解释流程、状态和交互关系的机制图保留在对应架构或专题中，不必集中迁移。

## 维护与同步

- 文件结构或职责变化时更新项目结构；功能契约变化时更新对应专题；跨模块关系或资源所有权变化时更新架构；任务入口变化时更新开发导航。按变化影响选择更新位置，不在每次开发后例行追加文件与测试索引。
- 调整既有说明时修改其主要归属，不在文末叠加同义补充。迁移或拆分内容时同步删除旧的完整副本，检查契约有无遗漏，并更新入口、交叉引用和锚点。
- 修改文档后检查差异、相对链接和章节锚点，确保导航描述与内容实际归属一致。

## 资料发现边界

不要仅为补充上下文而关闭 ignore 或其他文件过滤规则，也不要主动递归搜索被排除的文档。
